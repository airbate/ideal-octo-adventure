# CUDA 算子融合的边界：什么时候融合反而变慢

算子融合的目标是减少中间张量的读写，但融合并非越多越好。融合后如果寄存器溢出、并行度下降，或者引入大量 shape 分支，最终可能比两个简单 Kernel 更慢。

评估时先计算中间结果的字节数，再观察融合 Kernel 的寄存器和共享内存占用。对训练任务，还要考虑反向传播是否需要保存中间值；对推理任务，则要看 batch 和序列长度是否稳定。一个好的融合边界通常由“高复用、同 shape、同数据类型”的连续操作组成。

最终应使用目标 GPU 和真实 shape 做基准，记录 p50/p95 延迟、显存峰值与数值误差。融合是数据流优化，不是代码行数竞赛。
